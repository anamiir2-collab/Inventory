# نظام إدارة رصيد المخزن — Inventory Balance Management PWA

نظام محاسبة مخزن كامل يعمل بالكامل داخل المتصفح (بدون خادم وبدون قواعد بيانات خارجية)، مبني على ملف الإكسل الأصلي **«الرصيد 2025.xlsx»** ويحافظ على كل سجلاته التاريخية ومنطق حساب الرصيد كما هو.

> A complete offline-first inventory management PWA (Arabic RTL by default, English optional) built to replace an Excel-based inventory workflow while preserving its data and calculation logic.

## التشغيل على GitHub Pages

الطريقة الأولى (الأسهل):
1. ارفع الملفات إلى فرع `main`.
2. من إعدادات المستودع: **Settings → Pages → Source: Deploy from a branch → main / (root)**.
3. سيكون التطبيق متاحًا على `https://<username>.github.io/<repo>/`.

الطريقة الثانية (تلقائية): يوجد ملف `.github/workflows/deploy-pages.yml` ينشر الموقع تلقائيًا عند كل push إلى `main` — فقط اختر **Settings → Pages → Source: GitHub Actions** مرة واحدة.

## التشغيل محليًا

```bash
python3 -m http.server 8080
# ثم افتح http://localhost:8080
```

> لا تفتح `index.html` ببروتوكول `file://` — قاعدة البيانات (IndexedDB) والـ Service Worker يحتاجان `http://` أو `https://`.

## التثبيت كتطبيق (PWA)

افتح الرابط في Chrome/Edge على الحاسوب أو الهاتف، ثم:
- الحاسوب: أيقونة التثبيت في شريط العنوان أو زر «تثبيت» أعلى الصفحة.
- أندرويد: قائمة المتصفح → «إضافة إلى الشاشة الرئيسية».

بعد التثبيت يعمل التطبيق **بدون إنترنت** تمامًا، والبيانات محفوظة محليًا (IndexedDB) على الجهاز.

## منطق الحساب — مستند من الملف الأصلي (مهم)

تم فحص ملف «الرصيد 2025.xlsx» بالكامل قبل كتابة أي كود، وهذه هي الخريطة المؤكدة:

### ورقة «الرصيد» (917 صنفًا)
| العمود | المعنى | في التطبيق |
|---|---|---|
| A `Quality` | اسم الصنف | `quality` |
| B `GSM` | الجرام | `gsm` |
| C `Size` | المقاس (سم) | `size` |
| D `رصيد المخزن` | `=SUMIFS('انتاج و مبيعات'!$J:$J, ...!$D:$D, A, ...!$F:$F, B, ...!$G:$G, C)` | يُحسب ديناميكيًا |
| E `الوزن` | `=(C*D)*7.5` → المقاس × الرصيد × 7.5 | يُحسب ديناميكيًا |

### ورقة «انتاج و مبيعات» (24,392 سجلًا)
| العمود | المعنى | في التطبيق |
|---|---|---|
| A `p` | التاريخ (كل الخلايا تواريخ فعلية 2025-01-01 → 2026-11-20) | `date` |
| B `الوزن` | وزن بالكجم (اختياري) | `weight` |
| C `رقم اذن الصرف` | رقم الإذن | `permitNo` |
| D `اسم الصنف` | الصنف | `quality` |
| E `اسم العميل` | العميل/الجهة (بينها «انتاج» و«رصيد اول المدة») | `customer` |
| F `الجرام` | GSM | `gsm` |
| G `المقاس` | Size | `size` |
| H `اضافه` | كمية الإضافة | `addQty` |
| I `صرف` | كمية الصرف | `outQty` |
| J (بدون عنوان) | `=H-I` الصافي لكل سطر | يُحسب |
| K `تصفيه` | علامة تسوية (`غ` في 606 صفًا / `ض` في 531 صفًا) | `settlement` |

### القواعد المؤكدة
1. **الرصيد الحالي لكل صنف = مجموع (اضافه − صرف) على كل السطور المطابقة لثلاثية (اسم الصنف، الجرام، المقاس).** لا يوجد رصيد افتتاحي منفصل: أرصدة «رصيد اول المدة» هي سطور عادية ضمن عمود «اضافه».
2. **الوزن = المقاس × الرصيد × 7.5** (معامل قابل للتعديل من الإعدادات، الأصل 7.5).
3. **عمود «تصفيه» (`غ`/`ض`) لا يدخل في أي معادلة رصيد في الملف الأصلي** (تم التحقق: المعادلات تشير فقط إلى D/F/G/J) — لذلك يُحفظ كعلامة تسوية قابلة للفلترة دون تأثير على الرصيد.
4. صفوف «لاغي» (24 صفًا) وصفوف ناقصة الجرام/المقاس (155 صفًا) تُستورد كما هي ولا تدخل في أي رصيد — تمامًا كما تتصرف SUMIFS في الإكسل.
5. **التحقق:** أُعيد حساب أرصدة كل الـ 948 مجموعة بنفس منطق التطبيق وقورنت بالقيم المحفوظة داخل ملف الإكسل: **تطابق تام (0 اختلاف)**، وإجمالي الإضافات 65,601 والمنصرف 65,335 مطابق.
6. الأصناف الموجودة في الحركات وغير المدرجة في ورقة «الرصيد» (28 مجموعة) تُسجل تلقائيًا كمصنّفات بعلامة «من الحركات» حتى لا يضيع رصيدها.

### كشف التكرار عند الاستيراد
كل سجل له بصمة (تاريخ + صنف + جرام + مقاس + عميل + إذن + كميات + تصفيه). إعادة استيراد نفس الملف لا تضاعف البيانات (يُعرض عدد التكرارات المُتخطاة في المعاينة). الصفوف المتطابقة **داخل الملف نفسه** (179 صفًا موجود فعلًا في الملف الأصلي) تُحفظ كسجلات منفصلة لأنها قيود حقيقية مختلفة الأيام/الإذن — وتظهر عددها في المعاينة قبل الحفظ.

> ملاحظة: مكتبة SheetJS (النسخة المجانية) لا تكتب علم «ورقة RTL» داخل ملفات الإكسل المصدَّرة — المحتوى والأعمدة والعناوين العربية سليمة وتُعرض صحيحة، ويمكن تفعيل اتجاه الورقة من إعدادات إكسل عند الحاجة.

## اختبارات التحقق

يوجد اختبار آلي يشغّل **مسار الاستيراد الحقيقي** (`js/excel.js`) على الملف الأصلي داخل Node ويقارن النتائج بالقيم المحفوظة في الإكسل:

```bash
node scripts/test_import.js
# 21/21 ✓ — 24,392 حركة، 945 صنفًا، 948 رصيدًا مطابقًا 100%
```

تم اختبار التطبيق يدويًا أيضًا: استيراد الملف، تسجيل إضافة وصرف، تعديل وحذف مع تحديث الرصيد، التقارير والطباعة A4، تصدير الإكسل، النسخ الاحتياطي والاستعادة، العمل بدون إنترنت، و persistence بعد إعادة تحميل الصفحة.

## ملاحظات أمان البيانات

- البيانات تُخزن في IndexedDB على جهازك فقط — لا يوجد أي خادم أو رفع بيانات.
- الاستيراد الجديد لا يحذف أبدًا السجلات التاريخية (وضع «الاستبدال» اختياري صريح مع تأكيد).
- كل تعديل/حذف/استيراد/استعادة مسجل في سجل التدقيق مع نسخة قبل/بعد.
- نزّل نسخة احتياطية JSON دوريًا (الصفحة «النسخ الاحتياطي») — بيانات المتصفح قد تُفقد إذا مسح المستخدم بيانات الموقع يدويًا.

### English summary

A static, backend-free PWA (vanilla JS + IndexedDB + SheetJS + Chart.js) that imports the original Arabic inventory workbook, reproduces its exact balance logic — `balance = Σ(added − issued)` per `(quality, gsm, size)` combo, `weight = size × balance × 7.5`, verified with 0 mismatches against all 948 cached Excel results — and adds transaction entry, live balances, filtering, 7 printable A4 reports (page numbers, repeated headers, signature blocks), Excel export, JSON backup/restore, duplicate-aware import with preview, Arabic RTL UI with optional English, and full offline support via a service worker. Deploy: enable GitHub Pages on `main` (root) or the included Actions workflow.
